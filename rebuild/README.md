# MATH Foundation 0.3

Чистая Android-основа для возобновления MATH Client. **Minecraft пока не запускает.**
Старый `app/` и ветки Stage/parity не изменены. Новый Gradle-проект живёт
целиком в `rebuild/`; package `com.balzikz.mathclient.foundation` устанавливается
рядом со старым MATH и Minecraft.

## Что уже реализовано

- Подготовка игрового хоста в отдельном непубличном процессе `:game_host`.
  Потоковое копирование native-библиотек из всех установленных base/split APK
  в app-private runtime, SHA-256, проверка ABI/ELF, атомарное сохранение готового набора.
- Повторное использование runtime только после SHA-проверки APK и каждой библиотеки.
  Изменение версии, подписи или набора APK меняет идентификатор runtime;
  повреждённый кэш явно отклоняется. Незавершённые временные наборы очищаются при повторе.
- Граф DT_NEEDED с учётом SONAME. Внешние зависимости остаются непроверенными,
  циклы не превращаются в частичный порядок загрузки. Это метаданные, не вызовы dlopen.
- Resources установленной игры через публичный API PackageManager; SHA-сравнение
  одного уникального небольшого asset из каждого APK, содержащего assets.
  Полная совместимость игровых ресурсов этим не подтверждается.
- Жизненный цикл Activity и реальной SurfaceView; готовность среды снимается при pause,
  уничтожении surface и Activity. `HOST_ENVIRONMENT_READY` означает подготовленную среду,
  не загрузку Minecraft, JNI-регистрацию или игровой кадр.
- Отдельные `host-*.jsonl` и `host-result-*.txt` в сессии; runtime находится вне экспортов.

- Чтение интерфейса запуска установленной игры: все DEX из base/split APK,
  наследование классов, точные JNI-дескрипторы, поля и методы Minecraft/GameActivity,
  ссылки на вызываемые методы в стартовых классах. Используется smali-dexlib2 3.0.9;
  reflection, DexClassLoader и инициализация игровых классов не используются.
- ELF32/64 LE/BE: DT_NEEDED, SONAME, RUNPATH, выравнивание LOAD,
  экспортируемые JNI/Activity-функции. Поддержаны SHT_DYNSYM, DT_HASH и DT_GNU_HASH;
  недоступная таблица символов явно отличается от отсутствующего экспорта.
- Файлы nativeLibraryDir используются только при совпадении SHA с APK.
  Иначе одна ELF-библиотека временно извлекается в cache и удаляется после разбора;
  в отчёт попадают только метаданные. Лимиты: 64 MiB на DEX, 600 MiB на временный ELF.
- Краткий результат на главном экране: чтение завершено/неполное и причины.
  `metadataComplete=true` означает завершённый сбор метаданных, не готовый игровой хост.
- Чтение установленного `com.mojang.minecraftpe`: точная версия, versionCode,
  APK-подписи, base APK, все `splitSourceDirs`, nativeLibraryDir, Activity/Service metadata.
- SHA-256 APK и всех обнаруженных `.so`; заголовки ELF и ABI; счётчики assets/DEX.
  Чтение потоковое: библиотека размером сотни мегабайт не помещается целиком в RAM.
- Диагностическое окно в отдельном процессе `:probe`, загрузка собственной
  `libmathprobe.so` через JVM и проверяемый `RegisterNatives`.
- Собственный EGL/OpenGL ES 2.0 кадр: зелёная левая половина, тёмная правая.
  `PROBE_SWAP_OK` означает только успешный `eglSwapBuffers` нашего теста,
  не игровой кадр, не GameActivity parity и не доказательство показа пользователю.
- Append-only JSONL-журнал с session/PID/TID/process/временем; старые сессии не очищаются.
- Java stack trace; история завершений Android 11+; native tombstone при наличии
  в Android 12+. OS может уже не хранить trace — это явно отражается в отчёте.
- Просмотр, полное копирование небольшого текста, ZIP через FileProvider,
  выбор старой сессии. Ограничение Clipboard не приводит к незаметному усечению.
- 28 автономных тестов ядра и 28 тестов контрактов на собственных DEX/ELF-фикстурах;
  CI для APK/lint, JNI/EGL и чтения собственного APK на Android.

## Чего пока нет

Нет загрузки `libminecraftpe.so`, реализации Java/JNI-контракта Bedrock, объединённого с UI AssetManager,
GameActivity bridge, client hooks или модулей. Подготовка runtime реализована; игровой адаптер — ещё нет.
Наличие и корректный SHA APK **не означают** совместимость хоста.

Чужие APK, декомпилированные классы и бинарники не включаются в сборку/репозиторий.
Содержимое DEX-инструкций, строковые литералы, игровые assets и бинарники в ZIP не экспортируются.
Не нужны root, общий доступ к хранилищу, overlay, сеть или изменение Minecraft.
Никаких обходов авторизации, лицензии или защит в этом этапе нет.

## Собрать и проверить

Требования: JDK 17, Gradle 9.4.1, Android SDK 36 / build tools 36.0.0,
NDK 27.0.12077973, CMake 3.22.1. AGP 9.2.1 закреплён как в старом проекте.
Gradle Wrapper пока не включён; команды ниже требуют установленного Gradle.

Из корня репозитория:

```bash
bash rebuild/tools/test-core.sh
gradle -p rebuild :core:regressionTest :contract:regressionTest :app:lintDebug :app:assembleDebug
```

APK: `rebuild/app/build/outputs/apk/debug/app-debug.apk`.
Сборка включает arm64 для телефона и x86_64 для эмулятора. CI использует
существующий тестовый ключ репозитория, чтобы повторные APK устанавливались как обновления.
Ключ отладочный, не для production-публикации.

## Короткая проверка на телефоне

1. Установить 0.3 поверх Foundation 0.2: пакет и тестовая подпись сохранены.
2. Нажать **Подготовить игровой хост**, дождаться результата и вернуться к журналу.
3. Нажать **Поделиться сессией ZIP**. Подготовка может потребовать несколько минут
   и места для выбранных 64-битных библиотек. Это ещё не запуск Minecraft.
4. Для реализации адаптера нажать **Поделиться контрактом TXT** в сохранённой сессии 0.2.
   Кнопка отправляет полный последний `contract-*.jsonl` как обычный TXT, без изменения
   содержимого и без повторного сканирования. Альтернатива — приложить из ZIP
   `contract-*.jsonl` и `contract-result-*.txt` отдельно.

Собственный зелёный тестовый кадр повторно проверять не требуется.
Ограничения runtime и следующий блокер: [HOST_STAGE.md](HOST_STAGE.md).

ZIP включает технические пути/версии и иногда native trace. Перед отправкой
проверить содержимое: native trace может содержать сведения о памяти процесса.
В Foundation не загружается Minecraft и не запрашиваются игровые токены.
Полные native `.pb` не отображаются текстом; они доступны только в ZIP.
Сессии и экспорты сохраняются до очистки данных/удаления **Foundation** пользователем.

## Следующий рубеж

Базовый отчёт устройства и видимый тестовый кадр получены 14 сентября: Android 13,
Adreno 619, Minecraft 1.26.23.1. Подробности: [DEVICE_BASELINE.md](DEVICE_BASELINE.md).
Отчёт 0.1 не содержит Java/native-контракт. Сборка 0.2 извлекает необходимые
метаданные непосредственно на устройстве. Затем проверить контракт этого набора и добавить
минимальный host-adapter. Первый игровой кадр требует отдельного подтверждения.
Исторические версии 1.26.30.5 и 1.26.31.1 — факты старых опытов, не требования
к текущей установке и не список поддерживаемых версий.

Подробности восстановления: [ARCHAEOLOGY.md](ARCHAEOLOGY.md).

Проверка хоста в CI использует только собственный APK/asset через debug-extra
`debug_host_self=true`; Minecraft на эмуляторе не требуется и не загружается.

CLI для локального APK (метаданные JSONL в stdout):
`gradle -q -p rebuild :contract:inspectApk -Papk=/absolute/path/to/base.apk`.
В эмуляторном CI debug-extra `debug_contract_self=true` читает только APK самой
Foundation; отсутствие Minecraft в этой фикстуре ожидается и проверяется.
